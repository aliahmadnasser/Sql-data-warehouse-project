Data Dictionary: Gold Layer
This document describes the views and tables in the Gold layer of our data warehouse. The Gold layer provides business-ready data, optimized for reporting and analytics.

1. Gold.dim_customers
Overview
This view acts as the master directory for all customers. It combines customer data from our CRM system (the primary source for names and marital status) with our ERP system (the primary source for birthdates and location).

Key Features:

Surrogate Key: It creates a unique customer_key for each person to ensure fast, reliable connections to sales fact tables.

Data Enrichment: It pulls missing demographic data from the ERP system to create a complete customer profile.

Master Source Logic: If a customer's gender is missing in the CRM, the system automatically looks to the ERP system for the answer. If it is missing in both, it defaults to 'n/a'.

Columns:

Column Name	Description
customer_key	Primary Key. A unique number generated by the warehouse to link customers to their purchases.
customer_id	The original customer ID from the CRM system.
customer_number	The alphanumeric customer code used to link CRM and ERP systems together.
first_name	The customer's first name.
last_name	The customer's last name.
country	The customer's country of residence (standardized from ERP).
marital_status	The customer's marital status (MARRIED, SINGLE, or n/a).
gender	The customer's gender. CRM is the master source, but ERP is used as a backup if CRM data is missing.
birthdate	The customer's date of birth (from ERP).
create_date	The date the customer's profile was originally created in the CRM.

2. Gold.dim_products
Overview
This view acts as the master directory for all products. It combines core product information from the CRM system with descriptive categories and maintenance details from the ERP system. It creates a centralized, easy-to-read list of products for analytics and sales reporting.

Key Features:

Surrogate Key: Generates a unique product_key for every product to ensure fast and reliable connections to sales fact tables.

Historical Filtering: It intentionally filters out older, historical product records (where an end date exists) to keep only the active, current products in the dimension.

Data Enrichment: Joins with ERP category data to provide human-readable categories, subcategories, and maintenance requirements alongside the basic product info.

Columns:

Column Name	Description
product_key	Primary Key. A unique number generated by the warehouse to link products to sales transactions.
product_id	The original numeric ID from the CRM system.
product_number	The alphanumeric product code used to identify the item across systems.
product_name	The descriptive name of the product.
category_id	The ID linking the product to its master category.
category	The high-level category name (e.g., Bikes, Clothing) pulled from the ERP system.
subcategory	The more specific subcategory name pulled from the ERP system.
maintenance	Indicates whether the product requires maintenance (Yes/No).
cost	The cost of the product to the business.
product_line	The specific product line or series (e.g., Mountain, Road, Touring).
start_date	The date this product was officially introduced or became active.

3. Gold.fact_sales
Overview
This view acts as the central Fact Table in our Star Schema. It records every individual sales transaction. Because it contains the actual numbers (revenue, quantity, price) and connects directly to the Customer and Product dimensions, it is the primary table used for calculating business performance and sales metrics.

Key Features:

Star Schema Core: It uses foreign keys (product_key and customer_key) to link directly to the dim_products and dim_customers views.

Time Tracking: It records key dates for the transaction lifecycle, allowing analysts to track order dates, shipping dates, and payment due dates.

Financial Metrics: It holds the standardized sales amounts, quantities, and prices for accurate aggregation and reporting (e.g., calculating total revenue).

Columns:

Column Name	Description
order_number	The unique alphanumeric identifier for the sales order.
product_key	Foreign Key (FK1). Links to the Gold.dim_products table to identify exactly what was sold.
customer_key	Foreign Key (FK2). Links to the Gold.dim_customers table to identify who bought the item.
order_date	The date the customer placed the order.
shipping_date	The date the order was shipped to the customer.
due_date	The date the payment for the order is due.
sales_amount	The total revenue generated from this line item (calculated as quantity × price).
quantity	The number of units of the product purchased in this transaction.
price	The selling price of a single unit of the product.
